# Ключник - боты для своего VPN на AmneziaWG

Два бота к самодельному VPN-серверу: админский в **Telegram** и клиентский в
мессенджере **MAX**. Нужны, чтобы перестать раздавать конфиги руками.

Человек получает одноразовый код приглашения, присылает его боту в MAX (или
просто открывает ссылку) - и сразу получает свой `.conf` файлом и QR-кодом
картинкой. Дальше он сам смотрит своё состояние, сам перевыпускает ключ, если
потерял файл или сменил телефон, и сам проверяет, живой ли сервер. Админа
дёргают только тогда, когда сломалось что-то настоящее.

Писано под свой сервер и выложено как есть. Зависимостей, кроме стандартной
библиотеки Python, нет - ни pip, ни venv, ни докера.

## Что умеет

**Клиентский бот в MAX** (`maxbot.py`)

- приглашение по коду `XXXX-XXXX` или по ссылке `https://max.ru/<бот>?start=КОД`;
- выдаёт конфиг файлом и QR-кодом, инструкции по установке AmneziaVPN для
  Android, iPhone, Windows и Mac;
- «Моё состояние»: когда было последнее рукопожатие, сколько трафика;
- «Перевыпустить ключ» - сам, не дёргая админа. Адрес в сети сохраняется,
  старый конфиг перестаёт работать. Не чаще раза в сутки;
- «Добавить устройство» - второй конфиг (`имя-2`), лимит на человека настраивается;
- «Сервер работает?» - состояние службы, интернет с сервера, **доступность
  адреса из России** (пинг через московские узлы check-host.net) и число
  живых подключений;
- «Написать админу» - сообщение уходит админу в телеграм;
- админу в MAX: `/who`, `/broadcast текст`.

**Админский бот в телеграме** (`bot.py`)

- `/status` - нагрузка, память, диск, состояние служб; присматривает за ними
  сам и пишет, когда что-то упало или место на диске кончается;
- `/peers`, `/new имя`, `/revoke имя` - клиенты AmneziaWG;
- `/invite имя`, `/invite all`, `/invites` - коды приглашений в MAX;
- `/clients` - кто привязался и с каких устройств;
- `/traffic` (vnstat), `/journal`, `/restart <служба>`.

Приватные ключи клиентов на сервере не хранятся: конфиг отдаётся один раз в
момент выдачи. Поэтому «потерял файл» лечится не повторной отправкой, а
перевыпуском.

## Что нужно на сервере

- Linux с systemd (проверено на Ubuntu 22.04), права root;
- рабочий AmneziaWG: интерфейс `awg0`, юнит `awg-quick@awg0`, конфиг
  `/etc/amnezia/amneziawg/awg0.conf` (ставится скриптом Amnezia или вручную);
- `python3` 3.10 и новее, `qrencode`, по желанию `vnstat` для `/traffic`;
- бот в MAX (создаётся в **MasterBot**) и бот в телеграме (у **BotFather**).

## Установка руками

### 1. Файлы

```bash
git clone https://github.com/ivnshlm/kluchnik.git && cd kluchnik
apt-get install -y qrencode
mkdir -p /opt/vpnbot /var/lib/vpnbot /etc/vpnbot
install -m 644 awgcore.py clientsdb.py /opt/vpnbot/
install -m 755 maxbot.py bot.py /opt/vpnbot/
chmod 700 /var/lib/vpnbot /etc/vpnbot
```

### 2. Константы под свой сервер

В начале `awgcore.py` поправьте четыре строки:

```python
SRV_CONF = "/etc/amnezia/amneziawg/awg0.conf"  # конфиг сервера
IFACE = "awg0"                                 # имя интерфейса
POOL = "10.8.2."                               # подсеть клиентов, /24
PUBHOST = "203.0.113.10"                       # внешний адрес сервера
```

`PUBHOST` попадает в `Endpoint` клиентских конфигов. Параметры обфускации
(`Jc`, `S1`, `H1` и прочие) бот берёт из конфига сервера сам, вписывать их не
нужно.

В `bot.py` в словаре `SERVICES` перечислите свои службы, за которыми хотите
присматривать.

### 3. Конфиг с токенами

```bash
cp config.example.json /etc/vpnbot/config.json
chmod 600 /etc/vpnbot/config.json
nano /etc/vpnbot/config.json
```

Ключи:

| ключ | что это |
|---|---|
| `token` | токен телеграм-бота от BotFather |
| `claim_code` | одноразовая строка: ею вы назначите себя владельцем телеграм-бота |
| `max_token` | токен бота MAX от MasterBot |
| `max_claim_code` | то же для бота в MAX |
| `admin_id`, `max_admin_id` | появятся сами после привязки, руками не вписывать |

### 4. Снять вебхуки с бота MAX

**Обязательный шаг, иначе бот не получит ни одного сообщения.** В MAX вебхук
отменяет long polling: пока на токене висит хоть одна подписка, `GET /updates`
возвращает пустоту, а бот молчит и в журнале ничего нет. Если токен раньше
использовался для чего-то другого - подписки на нём остались.

```bash
cd /opt/vpnbot && python3 -c 'import maxbot; print(maxbot.mapi("GET", "/subscriptions"))'
```

Каждую найденную снять:

```bash
cd /opt/vpnbot && python3 -c 'import maxbot; print(maxbot.mapi("DELETE", "/subscriptions", {"url": "АДРЕС-ИЗ-СПИСКА"}))'
```

Должно остаться `{"subscriptions": []}`.

### 5. Службы

```bash
install -m 644 vpnbot.service vpnbot-max.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now vpnbot vpnbot-max
systemctl is-active vpnbot vpnbot-max
```

`RuntimeDirectoryPreserve=yes` в обоих юнитах стоит не случайно: каталог
`/run/vpnbot` общий, без него остановка одного бота унесла бы временные файлы
другого.

### 6. Привязать себя

Напишите своему телеграм-боту `/claim <claim_code>`, а боту в MAX -
`/claim <max_claim_code>`. Бот запомнит ваш id, код из конфига сотрётся, все
остальные для админских команд станут посторонними.

### 7. Раздать людям

```
/invite ivan      # код конкретному человеку
/invite all       # коды всем пирам, которых ещё нет в MAX
/invites          # какие коды ещё не использованы
```

Код живёт 7 дней и срабатывает один раз. Если пир с таким именем уже есть -
по коду ему перевыпустится ключ и придёт свежий конфиг; если нет - клиент
создастся с ближайшим свободным адресом.

Человеку удобнее ссылкой: `https://max.ru/<имя-бота>?start=КОД` (код без
дефиса). Открыл - и конфиг уже в чате, вводить ничего не надо. Ссылка
работает даже у того, кто бота уже открывал раньше. Код сообщением остаётся
запасным путём для старых версий приложения.

Имя бота для ссылки видно в MasterBot, выглядит как `id2310057xxxxxx_2_bot`.

## Грабли MAX Bot API

Собрано опытным путём, документация местами расходится с жизнью.

- хост `botapi.max.ru`. Задокументированный `platform-api2.max.ru` требует
  доверять корневому сертификату Минцифры;
- токен только заголовком `Authorization: <токен>`. Параметр
  `?access_token=` отвечает 401;
- **вебхук отменяет long polling** - см. шаг 4;
- вложения грузятся в два приёма: `POST /uploads?type=file|image` даёт url,
  туда multipart полем `data`. В ответ для файла приходит `{"token": ...}`,
  для картинки `{"photos": {"0": {"token": ...}}}`;
- после загрузки вложение доходит не мгновенно: первая отправка часто
  отвечает `attachment.not.ready`, нужно повторить через пару секунд (в коде
  это уже сделано);
- файл нельзя положить в одно сообщение с другими вложениями, поэтому конфиг
  и QR уходят двумя сообщениями;
- на нажатие кнопки обязательно отвечать `POST /answers?callback_id=...`, и
  **тело не может быть пустым**: нужен `notification` (всплывашка) или
  `message`. На пустом `{}` прилетает `message or notification required`;
- `chat_id` и `user_id` - разные числа. Чтобы написать человеку первым, надо
  запомнить его `chat_id` при первом обращении;
- `PATCH /me` не работает (`method.not.found`): имя, описание и аватарку
  бота меняют только в MasterBot;
- у check-host.net, которым проверяется доступность из России, свои нравы:
  без заголовка `User-Agent` он отвечает 403.

## Если нужен только бот в MAX

Телеграм-бот не обязателен, но коды приглашений выдаёт именно он. Без него:

```bash
cd /opt/vpnbot && python3 -c 'import clientsdb as c; print(c.fmt_code(c.invite_create("имя")))'
```

## Как устроено

| файл | зачем |
|---|---|
| `awgcore.py` | общая работа с пирами: выдать, отозвать, перевыпустить, прочитать состояние |
| `clientsdb.py` | SQLite: люди, устройства, коды, журнал действий |
| `maxbot.py` | клиентский бот в MAX |
| `bot.py` | админский бот в телеграме |

`awg0.conf` правят два процесса, поэтому любое изменение идёт под `flock`
(`/run/vpnbot-awg.lock`): иначе один бот затрёт пира, добавленного другим.
База клиентов - `/var/lib/vpnbot/clients.db`, SQLite в режиме WAL, тоже общая.

Что сознательно не сделано: заявок от незнакомых людей нет, доступ только по
коду от админа. Бот не отвечает тем, кого не знает, если это не похоже на код.
